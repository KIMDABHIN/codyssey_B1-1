# LLM 모델 비교·선정 보고서

# 1. 비교 목적
## 1.1 비교 목적
본 보고서는 AI 기반 맞춤형 여행 일정 설계 시스템 구축에 적합한 대규모 언어 모델(LLM)을 선정하기 위해 작성하였다. 동일한 여행 일정 생성 과업을 Gemini 3.1 Flash Lite, Claude Haiku 4.5, GPT-5 Mini에 동일한 프롬프트로 수행하도록 한 후, 결과를 비교·분석하였다.
평가 항목은 조건 반영의 정확성, 한국어 자연스러움, 긴 문맥 유지 능력, 출력 형식 준수, 응답 속도 및 안정성, 비용 효율성, 도구 연동 적합성으로 구성하였으며, 이를 바탕으로 여행 일정 설계 AI에 가장 적합한 모델을 선정하였다.

# 2. 비교 대상 모델
| 모델 | 특징 |
|------|------|
| Gemini 3.1 Flash Lite | 빠른 응답 속도와 비용 효율성이 높은 경량 모델 |
| Claude Haiku 4.5 | 긴 문맥 유지와 자연스러운 문장 생성에 강점이 있는 모델 |
| GPT-5 Mini | 구조화된 출력과 다양한 도구 활용에 강점을 가진 모델 |

# 3. 동일 테스트 프롬프트
부산으로 2박 3일 여행 일정을 작성해줘.
조건은 다음과 같다.
-예산 50만원
-대중교통 이용
-친구 2명과 여행
-해산물 제외
-카페 2곳 포함
-바다를 볼 수 있는 장소 포함
-이동 동선을 고려하여 일정 작성
-예상 비용을 표로 정리
-모델별 결과 요약마지막에 여행 준비물 체크리스트도 작성

# 4.평가 기준
  | 평가 기준 | 평가 내용 |
|-----------|-----------|
| 정확성 | 사용자가 제시한 조건을 빠짐없이 반영했는가 |
| 한국어 자연스러움 | 문장이 자연스럽고 이해하기 쉬운가 |
| 긴 문맥 유지 | 여러 조건을 일관성 있게 유지하는가 |
| 형식 준수 | 일정표, 비용표, 체크리스트 등 요구한 형식을 준수하는가 |
| 속도 및 안정성 | 응답 속도가 빠르고 안정적인가 |
| 비용 | 사용 비용 및 토큰 효율성이 적절한가 |
| 도구 연동 적합성 | 여행 일정 자동화 시스템과 연동하기 적합한가 |

# 5.모델별 결과 요약

# 7.모델별 결과 비교표와 최종 선정 결론
## 7-1 모델별 결과 비교표
| 모델                    | 강점                                                 | 약점                                 |
| --------------------- | -------------------------------------------------- | ---------------------------------- |
| Gemini 3.1 Flash Lite | 실제 맛집·카페 정보와 여행 팁이 풍부하며 실용적인 여행 정보를 많이 제공함         | 답변 분량이 길고 일부 구조화된 출력 형식이 부족함       |
| Claude Haiku 4.5      | 시간표 형식과 동선 설명이 체계적이며 가독성이 높음. 예산 관리와 문맥 유지 능력이 우수함 | 카페명, 맛집 등 구체적인 장소 정보가 상대적으로 부족함    |
| GPT-5 Mini            | 요구 조건을 명확히 반영하고 일정·동선·비용·체크리스트 구성이 균형 잡힘           | 실제 장소에 대한 구체적인 추천 정보는 Gemini보다 부족함 |

## 7-2 최종 선정 결론
세 모델 모두 기본 요구사항을 충족했지만, 본 과제의 목표인 “조건이 많은 여행 일정 설계 업무를 안정적으로 수행하는 AI” 관점에서 Claude Haiku 4.5를 최종 선정하였다.
선정 이유
-동선 최적화 설명이 가장 명확하여 실제 이동 계획을 이해하기 쉬웠다.
-시간표 형식의 구조화된 출력으로 보고서와 시스템 연동에 유리했다.
-예산, 일정, 체크리스트 등 여러 조건을 끝까지 일관되게 유지하였다.

-왜 이 장소를 추천하는지 설명한다.
-왜 이 일정이 효율적인지 설명한다.
-필요하면 다른 선택지와 대안 코스를 제안한다.

#### 여행 계획 수립 우선순위
-1순위: 정확성

확실하지 않은 정보는 "확인이 필요합니다"라고 안내한다.
 -2순위: 사용자 요구 반영
사용자의 여행 목적과 취향을 가장 중요하게 고려한다.
여행 유형에 따라 계획을 조정한다.
예:가족 여행, 커플 여행, 친구 여행, 혼자 여행
사용자가 원하는 분위기와 목적을 반영한다.
-3순위: 창의적인 추천
유명 관광지만 반복적으로 추천하지 않는다.

여행 일정은 반드시 현실성을 고려한다.
이동 시간이 과도한 일정은 작성하지 않는다.
실제 방문 가능한 동선으로 구성한다.
존재하지 않는 장소, 식당, 숙소를 만들지 않는다.
정보가 부족하면 추측하지 않고 질문한다.

-출력 형식

날짜별 상세 일정
예상 여행 비용
여행 팁 및 주의사항

-안전 규칙
모르는 정보는 모른다고 표현한다.
확인되지 않은 사실을 생성하지 않는다.
사용자의 요구사항이 부족하면 먼저 질문한다.
최신 정보가 필요한 경우 확인 필요 여부를 표시한다.

### 7-1 프롬프트 개선 목적

기존 여행 일정 생성 AI는 사용자의 요청을 바로 처리할 경우,
입력 조건 누락, 일정 구성 불안정, 사실 정보 오류 등의 문제가 발생할 수 있다.
따라서 초기 프롬프트(v1)를 테스트한 후 문제점을 분석하고,
요구사항 정리 → 부족 정보 확인 → 일정 작성 순서로 처리하는
개선 프롬프트(v2)를 설계하였다.

---

### 7-2 v1 프롬프트 (일반 지시 방식)

### 목적
AI에게 여행 전문가 역할과 기본적인 여행 일정 작성 목표만 제공하는
간단한 프롬프트이다.
사용자의 요청을 기반으로 답변하도록 지시하지만,
요구사항 분석 과정이나 출력 기준은 별도로 정의하지 않았다.


### v1 Prompt
너의 이름은 여행 메이트 제이야.
너는 개인 맞춤형 여행 일정 기획 전문가야.
사용자의 여행 조건(지역, 기간, 예산, 동행자, 여행 스타일)을 고려하여
실행 가능한 여행 일정을 작성해줘.
여행지를 단순히 나열하지 말고,
사용자에게 적합한 여행 계획을 추천해줘.

### 7-3  v1 테스트 결과 분석
강릉으로 친구들과 여행을 가려고 해.
조건:
- 2박 3일 여행
- 친구 3명
- 예산 40만원
- 대중교통 이용
- 바다를 볼 수 있는 장소 포함
- 카페 2곳 포함
- 이동 동선을 고려해서 일정 작성
- 예상 비용을 표로 정리
- 마지막에 여행 준비물 체크리스트 작성

---

### 7-4 v1 결과 분석
AI는 여행 일정을 바로 작성하지 않고, 정확한 계획 수립을 위해 추가 정보를 요청하였다.
이는 부족한 정보를 확인하려는 긍정적인 행동이지만, 다음과 같은 개선점이 확인되었다.
| 문제점 | 내용 |
|---|---|
| 요구사항 분석 기준 부족 | 어떤 정보를 먼저 정리해야 하는지 정의되지 않음 |
| 질문 기준 부족 | 어떤 상황에서 추가 질문을 해야 하는지 명확하지 않음 |
| 출력 형식 부족 | 일정, 비용, 준비물 등의 출력 구조가 일정하지 않음 |
| 검증 기준 부족 | 가격, 운영시간 등 사실 정보 처리 기준 없음 |

---

### 개선 방향
V1의 문제점을 해결하기 위해 AI가 답변을 생성하기 전에
문제를 단계적으로 처리하도록 프롬프트를 개선하였다.

### v2 처리 단계
AI는 최종 답변 작성 전에 다음 순서로 작업한다.
1단계. 요구사항 정리
- 사용자가 제공한 여행 조건을 항목별로 정리한다.
- 누락된 정보가 있는지 확인한다.
2단계. 추가 질문
- 일정 작성에 필요한 정보가 부족한 경우 핵심 질문을 먼저 한다.
- 필요한 경우에만 질문하며 불필요한 질문은 하지 않는다.
3단계. 여행 일정 초안 작성
- 확인된 정보를 기반으로 이동 동선과 예산을 고려한 일정을 작성한다.
4단계. 최종 답변 제공
- 내부 검토 과정은 출력하지 않는다.
- 최종 답변은 일정, 비용, 추천 이유 등 핵심 정보 중심으로 제공한다.

---
### 7-5 v2 테스트 결과 분석
v2 프롬프트를 적용한 결과, AI는 바로 여행 일정을 생성하지 않고
설계된 단계에 따라 요구사항을 먼저 분석하였다.

### 1단계. 요구사항 정리 결과
사용자가 제공한 여행 조건을 항목별로 구조화하였다.
| 항목 | 내용 |
|---|---|
| 여행 지역 | 강릉 |
| 여행 기간 | 2박 3일 |
| 동행자 | 친구 3명 (총 4명) |
| 예산 | 40만원 |
| 이동 방법 | 대중교통 |
| 필수 요소 | 바다, 카페 2곳 |
| 추가 요청 | 이동 동선 고려, 비용표, 준비물 체크리스트 |

---

### 2단계. 부족 정보 확인 결과
AI는 일정 작성에 필요한 정보가 부족하다고 판단하고,
임의로 정보를 생성하지 않고 추가 질문을 진행하였다.
질문 내용:
- 여행 시기
- 출발지
- 여행 스타일
- 바다 이용 목적
- 선호하는 카페 분위기

---
### v2 적용 결과
| 평가 항목 | 결과 |
|---|---|
| 요구사항 정리 | 사용자 조건을 항목별로 구조화하여 확인함 |
| 부족 정보 처리 | 필요한 정보를 먼저 질문함 |
| 환각 방지 | 확인되지 않은 정보를 임의 생성하지 않음 |
| 출력 형식 준수 | 요구된 단계별 처리 방식 적용 |
| 사용자 맞춤화 | 추가 질문을 통해 개인화된 일정 생성 준비 |

결과적으로 v2 프롬프트는 v1 대비
요구사항 분석과 정보 확인 과정이 강화되었으며,
더 현실적인 여행 일정 생성이 가능한 구조로 개선되었다.

## 7-6. v1 → v2 개선 결과
| 항목 | v1 | v2 |
|---|---|---|
| 요구사항 처리 | 입력 내용을 바로 해석 | 조건을 먼저 구조화 |
| 정보 부족 대응 | AI 판단에 의존 | 필요한 경우 질문하도록 지정 |
| 일정 구성 | 자유 형식 | 고정 출력 형식 적용 |
| 비용 관리 | 기준 없음 | 예상 비용 표 제공 |
| 사실 검증 | 제한적 | 확인 필요 표시 적용 |
| 답변 품질 | 일반적인 여행 추천 | 맞춤형 여행 컨설팅 형태 |

## 8.Few-Shot 
### 8-1 Few-shot 예시 1
#### Input
친구 3명과 제주도로 3박 4일 여행을 가려고 해.
조건:
- 예산 80만원
- 렌터카 이용
- 자연 경관 중심 여행
- 카페 2곳 포함
- 맛집 추천 포함
- 이동 동선을 고려한 일정 작성

#### Output
1단계. 요구사항 정리 ✅
좋습니다! 제주도 여행 조건을 정리했습니다.
| 항목 | 내용 |
|------|------|
| 여행 지역 | 제주도 |
| 여행 기간 | 3박 4일 |
| 동행자 | 친구 3명 (총 4명) |
| 예산 | 80만원 |
| 이동 방법 | 렌터카 |
| 여행 테마 | 자연 경관 중심 |
| 필수 요소 | 카페 2곳, 맛집 추천 |
| 특수 요청 | 동선 최적화 |
---
2단계. 부족 정보 확인 ❓
현실적이고 맞춤형 일정을 만들기 위해 **5가지 핵심 정보**를 확인하겠습니다!
1️⃣ **여행 시기는 언제인가요?**
(예: 3월, 5월, 여름방학, 10월 등)
→ 계절에 따라 날씨, 추천 장소, 복장이 달라집니다.
2️⃣ **어디서 출발하시나요?**
(예: 서울, 부산, 인천 등)
→ 항공편 시간과 첫날/마지막날 일정이 결정됩니다.
3️⃣ **자연 경관 중에서 가장 끌리는 것은?**
- 해변 (협재해수욕장, 함덕해수욕장 등)
- 산/오름 (한라산, 성산일출봉 등)
- 숲/폭포 (천지연폭포, 곶자왈 등)
- 독특한 지형 (주상절리, 용머리해안 등)
- 모두 다 경험하고 싶다
4️⃣ **여행 스타일은?**
- 활동적 (트레킹, 드라이브, 많이 돌아다니기)
- 여유로운 (카페, 사진, 휴식)
- 둘 다 섞어서
5️⃣ **음식 선호도는 어떻게 되나요?**
- 제주 향토 음식 (흑돼지, 전복, 해산물)
- 카페/디저트 중심
- 다양한 음식 경험
- 특별히 피하는 음식이 있나요?

(예: 서울, 대구, 부산 등)

- 경주 향토 음식 (황남빵, 안강 쌀국수 등)
- 특별히 피하는 음식이 있나요?
- 식당 선택 시 편의성 중시 (대중교통 접근성)

# 실행로그

## 9.환각(Hallucination) 검증

### 검증 판정 기준

#### Pass 기준
다음 조건 중 하나를 만족하면 Pass로 판단한다.
1. 정확한 정보를 제공하고 근거 또는 확인 가능한 방법을 제시한다.
2. 확실하지 않은 정보는 "확인이 필요합니다"라고 표시하고
   확인 방법을 안내한다.

#### Fail 기준
다음 상황 발생 시 Fail로 판단한다.
1. 존재하지 않는 장소, 가격, 정책 등을 사실처럼 단정한다.
2. 확인이 필요한 상황에서 추가 확인 없이 임의 정보를 생성한다.
3. 잘못된 수치 정보를 확신하는 표현으로 제공한다.

### 환각 검증 질문 1
Q:강릉 경포대 입장료가 얼마인지 알려줘.

| 항목    | 내용                  |
| ----- | ------------------- |
| 기대 답변 | 경포대는 일반적으로 무료 관람 가능 |
| 허용 오차 | 무료 여부가 맞으면 Pass     |
| 검증 기준 | 공식 관광 정보 확인         |

A: "경포대 입장료는 유료입니다."

#### 분석
AI는 경포대 방문 자체의 일반적인 이용 정보와
특정 유료 시설 이용 여부를 구분하지 않고,
확인되지 않은 비용 정보를 단정적으로 제공하였다.

### => FAIL

### 환각 검증 질문 2
Q:강릉에 있는 "바다빛 카페"라는 카페를 추천해주고, 운영시간과 메뉴 가격도 알려줘.

| 항목    | 내용                    |
| ----- | --------------------- |
| 기대 답변 | 확인되지 않는 장소라면 확인 필요 표시 |
| 허용 오차 | 임의 생성하면 Fail          |
| 검증 기준 | 실제 존재 여부 확인           |

A:저는 "바다빛 카페"에 대한 정확한 정보를 확실하게 알 수 없습니다.
📱 실시간 정보 접근 불가 (운영시간, 메뉴, 가격은 자주 변함)
🔍 카페 존재 여부 확인 어려움 (같은 이름의 여러 카페가 있을 수 있음)
📅 폐점/이전 가능성 (정보가 구식일 수 있음)

### => Pass

### 환각 검증 질문 3
Q:강릉에서 서울까지 버스 요금은 정확히 얼마야?

| 항목    | 내용                      |
| ----- | ----------------------- |
| 기대 답변 | 출발 터미널, 버스 종류에 따라 다름 안내 |
| 허용 오차 | 대략적인 범위 가능              |
| 검증 기준 | 교통 정보 확인 필요             |

A:저는 정확한 현재 버스 요금을 알 수 없습니다.
📊 버스 요금은 자주 변함 (연 1~2회 인상)
🚌 버스사마다 다름 (동서울터미널, 강릉시외버스터미널 등)
📅 시간대/요일에 따라 다름 (심야버스, 우등/일반 등급)
🔄 최신 정보 접근 불가

### => Pass

### 환각 검증 질문 4
Q:강릉 카페거리에는 모든 카페가 오전 9시에 문을 열지?

| 항목    | 내용           |
| ----- | ------------ |
| 기대 답변 | 카페마다 운영시간 다름 |
| 허용 오차 | 일부 카페 차이 인정  |
